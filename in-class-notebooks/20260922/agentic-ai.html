02 · What an agent is

An agent is a system in which a model chooses its own actions and takes them through tools

Target 1:30 to 2:45. Four clicks, two parts each, with one sentence per part. Slides 8 to 10 go deeper.

Read the heading slowly. The agent is the whole system, and the model is one part of it. Choosing the next step is what makes it agentic, since a script that calls a model in a fixed order is automation. A loop and a stated goal are common and useful, and neither is required.

Source: Anthropic, "Building effective agents" (December 2024), which describes agents as systems in which models direct their own processes and tool use, and separates them from workflows, in which code sets the steps.

  1. Model: the neural network, which predicts the next token. Gloss the word the first time you say it, i.e., a token is a word piece, and 1,000 tokens is about 750 English words.
  2. Harness: the program around it (Claude Code, Codex, Cursor).
  3. Context: everything the model receives on this turn. The context window is the limit on how much of it fits, which slide 8 illustrates.
  4. Tools: the model requests an action, the harness runs it, and the result comes back into the context.
  5. Memory: notes on disk, reloaded into the context at the start of a session.
  6. Skills: instructions loaded only when relevant.
  7. Loop: the think, act, observe cycle that repeats.
  8. Goal: the condition that each turn is judged against.
  • A non-coding example to say aloud: an agent searching for papers reads the results, refines the query, and checks each citation before reporting.
02 · What an agent is

Agency comes in degrees

Single call

One prompt, one answer.

"Summarize this abstract."

Workflow

Fixed steps written in code, with a model call at each step.

Extract, classify, and tabulate 5,000 PDFs.

Router

The model picks one path from a fixed menu.

Send each email to the right queue.

Agent

The model chooses its tools and steps as it goes.

"Find and fix the bug."

Long-running agent

Works for hours toward a goal that can be checked.

Migrate the code until all tests pass.
← Code decides. Predictable, cheaper, easy to test.
Model decides. Flexible, handles surprises, harder to verify. →

Target 2:45 to 3:30. No clicks. Many products sold as "agents" are workflows, and a workflow is often the right design.

  • Research example for the workflow: classifying thousands of documents is better as a fixed pipeline that can be validated and rerun.
  • An agent is worth its extra cost when the steps cannot be written in advance (debugging, exploration).
  • Say the operating rule aloud rather than printing it: use the least autonomy that gets the job done. Anthropic's guide gives the same advice, i.e., start simple, and add autonomy only when simpler designs fail.

Target 3:30 to 5:15. Four clicks, one era each, about 25 seconds per era.

  • Ask. GPT-3 (2020) showed in-context learning. Chain-of-thought prompting (Jan 2022) and ReAct (Oct 2022) showed that models do better when they write out steps, and ReAct interleaved those steps with actions. ChatGPT brought chat models to the public.
  • Augment. AutoGPT ran GPT-4 in a loop in March 2023 and drew wide attention, but it rarely finished real tasks with the models of that year. Function calling and retrieval gave models tools and documents. Retrieval was published in 2020 and became common in 2023.
  • Reason and act. Reasoning models, computer use, and MCP (introduced by Anthropic and now widely supported).
  • What a reasoning model does differently (optional depth, skip it if the timer is tight). It is trained to write out its reasoning before it answers, and the answer is generated in the same context as that reasoning, so the model reads its own intermediate steps as it writes the final response. Those reasoning tokens are billed as output, which is why a reasoning model costs more per answer. Providers show a summary of the reasoning rather than the raw text. Whether the reasoning is carried into later turns depends on the model and the interface, and it is commonly dropped, so the next turn sees the answer but not the steps. An agent in the middle of a tool-use loop is normally given its own reasoning back, so that a multi-step plan survives the tool call.
  • Delegate. Agents that work in files and terminals, skills, and goal modes (Claude Code's /goal shipped in May 2026, and Codex added a goal mode the same spring).
  • The bottom row carries the argument: our job changes in each era. The next slide names those jobs.

Target 5:15 to 5:45. Four quick clicks, built from the inside out.

  • Prompt engineering covers wording, examples, and format, and it is still useful.
  • Context engineering starts from the fact that the prompt is a small part of what the model sees. Files, tool results, memory, and history often matter more.
  • Loop engineering designs the cycle (what feedback the agent gets, and when it stops) instead of each message.
  • Goals state a checkable definition of done for the loop to work toward.
  • The last two terms are new, and people use them loosely.
  • The model takes on more of the work at every level. What changes for us is the altitude of the design, from the wording of one message to the definition of done.
03 · How we got here

The tasks agents can finish keep getting longer

Data: METR Time Horizon 1.1 (retrieved 19 September 2026).

Target 5:45 to 7:15. One chart to show why the vocabulary changed so quickly. Two clicks.

  • Reading rule, said aloud: the height of a point is the human time a task takes at which the model succeeds half the time. It is not how long the agent runs. Pick a model and read its height. GPT-4 (2023) is at about 4 minutes of human work, and Claude Opus 4.6 (Feb 2026) is at about 12 hours.
  • Scope, said aloud: METR Time Horizon 1.1 uses software engineering, machine learning, and cybersecurity tasks, not all work. Some human times are expert estimates, and the oldest points come from an earlier, simpler task set.
  • The top point, Claude Mythos Preview, sits above 16 hours, which is past what the task suite measures reliably. It is drawn in red for that reason and is excluded from the fitted line.
  • First click: the dashed line is a least-squares fit to frontier models since 2023. Give the rate in speech rather than reading a label, i.e., the horizon has been doubling roughly every four months.
  • Second click: the open diamonds are the same models at 80% success. Mythos Preview drops from 17.4 hours to about 3 hours, and Opus 4.6 from 12 hours to 70 minutes. Across these models the stricter horizon runs four to ten times shorter, and both fitted lines rise at a similar rate, so the gap is not closing.
  • The 80% series is the stricter measure, i.e., the task length the model finishes four times in five on this benchmark. Say plainly that it is a benchmark number rather than a promise about anyone's own work, which still needs its own checks.
04 · The parts in detail

The prompt is a small part of what the model sees

Prompt · prompt engineering

The prompt is the instructions. The harness writes a system prompt, and the user writes the user prompt.

Prompt engineering is crafting the wording, examples, and output format.

Context · context engineering

Context is everything the model receives on one call, which may include history, summaries, files, and tool results.

Context engineering is choosing what goes in, what stays out, and when.

Context rot
Long or cluttered context can reduce accuracy well before the window is full, and details in the middle are the most likely to be missed. Harnesses respond by summarizing old turns (compaction), saving notes to files, and giving subtasks to subagents, each of which starts a separate context holding only its instructions and the subtask.

Target 7:15 to 8:30. No clicks. The key conceptual slide for experienced users.

  • In an agent session, the typed request is a small fraction of the context. In this made-up example, tool results take 64k of the 103k tokens in use (about 62%).
  • Say here that the model retains nothing between calls, so the harness resends the whole conversation, or a summary of it, on every turn. That is why context has a budget at all, and why a long session costs more.
  • Context engineering spread as a term in mid-2025, popularized by Tobi Lütke and Andrej Karpathy. It holds that an agent's output depends more on what it is shown than on how the request is worded.
  • Context rot: accuracy can drop in long or cluttered sessions, and information in the middle of a long context is the most likely to be missed (the "lost in the middle" result). Practical advice is to start a new session for a new task, keep standing instructions in files, and ask for summaries.
04 · The parts in detail

Tools, memory, and skills

Tools

Functions the model can request

The model writes a structured request. The harness runs it and returns the result.

{ "tool": "run_command",
  "input": {
    "cmd": "pytest tests/" } }
MCP (Model Context Protocol) is an open standard, so one tool server works in many harnesses.
Memory

Notes that persist between sessions

The model retains nothing between sessions. Memory is text the harness saves and reloads.

# AGENTS.md
- Run the tests before reporting
- data/raw is read-only
- March files use MM/DD/YYYY
Using an agent does not change the model's weights. Memory is more context, loaded at the start of a session.
Skills

Instructions loaded when needed

A folder of instructions and scripts for one kind of task.

skills/
  make-figure/
    SKILL.md  style.py
  verify-citations/
    SKILL.md
The agent sees each skill's name and description, and it reads the full instructions only when a task matches.

Target 8:30 to 9:45. No clicks. About 25 seconds per card.

  • Tools: the model never touches the computer. It writes a request, and the harness decides whether to run it, which is where permissions are enforced. pytest is a program that runs a project's automated tests.
  • MCP: a Zotero or database MCP server written once works in any harness that supports the protocol.
  • Memory: AGENTS.md, CLAUDE.md, and GEMINI.md are plain text files that anyone can read and edit. A line in memory is an instruction, not an enforced rule. Read-only data is enforced by permissions, not by a note.
  • Skills (introduced by Anthropic in Oct 2025 and now an open format) load only when relevant, which keeps the context small.
04 · The parts in detail

The loop repeats until a checkable goal is met

Loop engineering

Designing the cycle the agent repeats

  • Feedback it can use, such as tests, validators, compiler errors, or a reviewer model
  • Stop rules, i.e., a success condition plus a step or cost budget
  • Checkpoints where it pauses for a person
  • Fresh starts by splitting long work across subagents
Goals
Vague

"Clean up the survey analysis."

Checkable

"All 42 tests pass, Figure 3 regenerates from the script, and Table 2 matches its output."

Goal modes (2026) keep an agent working across turns. Claude Code asks a separate model to judge the condition from the conversation, and Codex judges its own work. Either judgment still needs evidence and review.

Target 9:45 to 11:00. No clicks.

  • The think, act, observe cycle follows the ReAct pattern from 2022, and most agent products run a version of it.
  • Loop engineering: once the agent loops on its own, the design of the loop matters more than the wording of any one message. The most useful feedback is something the agent can run itself, such as a test suite.
  • Goals: a vague goal leaves the agent to decide when it is done, whereas a checkable goal can be tested.
  • Goal checkers judge from what they can see. Claude Code's checker reads the conversation and does not rerun the tests, so the evidence still has to be in front of a person.
  • For researchers, "checkable" often means a known answer, a validation set, or a reproduced number.
05 · Definitions

Definitions

Agent
A system in which a model chooses its own actions and takes them through tools
Model
The neural network. Tokens in, tokens out, nothing retained between calls
Token
A word piece, the unit models read, write, and bill by
Harness
The program around the model that runs the loop, tools, and permissions
Prompt
The instructions given to the model (system and user)
Prompt engineering
Crafting the wording, examples, and output format
Context
Everything the model receives on one call
Context engineering
Choosing what enters the context, what stays out, and when
Tools
Functions the model requests and the harness executes
MCP
The Model Context Protocol, an open standard for connecting tools to harnesses that support it
Memory
Saved notes reloaded into context in later sessions
Skills
Packaged instructions and scripts, loaded only when relevant
Loop
Think, act, observe, repeat
Loop engineering
Designing the feedback, stop rules, and checkpoints of the loop
Goal
A checkable condition that defines done
Subagent
A helper agent given one subtask, with a context of its own
