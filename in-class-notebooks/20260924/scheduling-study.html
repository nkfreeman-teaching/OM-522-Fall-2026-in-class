Sensitivity to the sampled cases

How stable is the recommendation?

Each repeat draws ten cases with replacement within each arrival pattern and reruns the default ranking. This checks sensitivity to these synthetic cases. It does not predict performance in a new factory. Read the methods and limits.

The report is self-contained and can be opened or shared without a server or network connection.

What was tested

Thirty generated instances contain 40 to 80 jobs each. A single machine handles one job at a time. Jobs have processing times, release times, due dates, and priority weights. Fixed setup times are zero.

BacklogAll jobs arrive in the first 30 time units, leaving many jobs waiting.
Steady arrivalsJobs arrive throughout the horizon, and the machine is sometimes idle.
Rush ordersAbout 20% of jobs are short, heavily weighted, and due soon after release.

Four outcomes

Total completion timeThe sum of each job's finish time.
Weighted total completionThe same sum, with each job's finish time multiplied by its priority weight.
Maximum latenessThe largest finish time minus due date for any job. A negative result means every job finished early.
Weighted tardinessThe sum of late time multiplied by priority weight. Early jobs add zero.

Smaller is better for every outcome.

How schedules were built

A dispatch rule picks the next job among those already released. The machine waits for the next release only when no job is available. Ties use job identifier order.

Earliest due date (EDD)Pick the job with the earliest due date.
Shortest processing time (SPT)Pick the shortest available job.
Critical ratio (CR)Pick the smallest ratio of time until due date to processing time.
Weighted shortest processing time (WSPT)Pick the smallest processing time divided by priority weight.

Three improvement moves

Adjacent swapExchange two neighboring jobs.
Any-pair swapExchange any two jobs in the order.
Subsequence reversalReverse a consecutive block of jobs.

The search accepts the first move that strictly improves the chosen outcome and repeats until no move in that neighborhood helps. Each revised order runs jobs in sequence. It may wait for a later job even when another job is ready.

How methods were compared

Each rule and improvement move is run separately for each of the four target outcomes. Thus, a method can create four different schedules for the same case. The comparison chooses one rule and one move that work across target choices. It does not choose one schedule that balances all four outcomes at once.

For each case and target, the ranking benchmark is the lowest target value found among the 12 methods. A method's gap is its value minus that benchmark, divided by the larger of 1 and the benchmark's absolute value. For example, 105 compared with a best tested value of 100 gives a 5% gap. All benchmarks in these cases are positive. The best tested value is not a proven optimum.

Each of the three arrival patterns and four outcomes defines one group. Ten paired case gaps are averaged in each of these 12 groups. The default ranking minimizes the largest group-average gap. The equal-average option weights all 12 group averages equally. Other options average across the selected outcome or arrival pattern. Exact ties use the default score as a second criterion.

The trade-off table uses a different benchmark. It compares each outcome with the best of all 48 schedules made for that case, across the 12 methods and four search targets.

How far the finding travels

Resampling check

Two thousand repeats draw ten cases with replacement from each arrival pattern. Every repeat keeps method comparisons paired within each sampled case and recalculates the default ranking. The displayed share is how often a method ranks first under that resampling. It describes sensitivity to the supplied synthetic cases, not the probability of winning on a new factory's jobs.

Computation

An evaluation scores one candidate job order. The three improvement moves inspect different numbers of candidates. Reported milliseconds come from this implementation on this machine and are useful for comparing methods here, not predicting runtime on another machine.

Limits

The 30 cases were generated from three patterns with one fixed set of seeds. Real systems may have sequence-dependent setup, breakdowns, several machines, or different priority weights. Test the selected method on fresh cases from the intended setting before adopting it. A single schedule that balances all four outcomes would require a separate combined-objective design.
